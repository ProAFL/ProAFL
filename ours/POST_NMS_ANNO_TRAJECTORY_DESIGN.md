# 用 NMS 后预测框构建逐 anno 的 conf / IoU 训练轨迹

## 1. 要解决什么问题

我们有 50 个 epoch 的 checkpoint，以及每个 checkpoint 对训练图像保存的
**NMS 后预测框**。希望给标注文件中每个实际存在的 anno 建立两条轨迹：

- 这轮相关预测框的 **conf**；
- 同一个预测框与 anno 的 **IoU**。

再从这两条轨迹提取过程特征，给每个 anno 一个可疑度分数，
将 clean 和任意 fault anno 排开。**只做 clean/fault 排序，不预测错误类型**；
排序时不使用已知干净标注。缺失标注没有 anno ID，不属于排名对象。

推荐把 conf 和 IoU **分开保留**。例如两轮分别得到
$(\mathrm{conf},\mathrm{IoU})=(0.9,0.2)$ 和 $(0.3,0.6)$，
两轮的乘积都为 0.18，但模型表现显然不同：
前者检测分数高而框不准，后者框较准而检测分数低。
乘积可以做对照实验，不作为主过程度量。

> **边界：**从 NMS 后框只能观察已保留的检测结果。
> 如果某个 anno 在一轮没有相关预测框，就不存在实测的
> “该 anno 的预测框 conf / IoU”。为使轨迹长度固定，
> 我们另定义两个**检测支持度**，这轮记 0，并同时记录“无相关框”。
> 这两个 0 不是模型原始输出的 conf / IoU。

## 2. 为什么改当前匹配

现有 [<code>search_match_PG2</code>](match_metrics/match_and_collect_metrics.py)
要求预测类别等于 anno 类别、IoU 至少为 0.5，再做一对一贪心匹配。
某轮不满足条件时，现有流程把 conf 和 IoU 填成 0；
很多 50 轮从未正式匹配的 anno 因而得到相同过程特征。

新方案保留旧规则的“正式匹配”结果用于对照，
但主轨迹改成**逐 anno 独立选框**：

- 只看该图该轮的 NMS 后预测框；
- 要求预测类别与 anno 类别相同，且两个框有实际重叠；
- 不设置 0.5 的正式匹配阈值；
- 一个预测框允许被多个 anno 考察，不做一对一排他分配。

这样，IoU 为 0.3 的同类预测框虽然不是“正式匹配”，
仍可贡献这一轮的 conf 和 IoU。
若没有任何同类重叠框，仍然没有相关预测框；
本方案不能凭空恢复被 NMS 或置信度阈值过滤的预测。

## 3. 一张图、一轮、一个 anno：具体怎么选框

设 anno $a$ 的标注类别为 $c_a$、框为 $B_a$。
该图在 epoch $t$ 保存的 NMS 后预测集合为 $D_t$。
每个预测框 $d$ 有类别 $c_d$、conf $q_d$ 和框 $B_d$。

先找出**同类别且有重叠**的预测框：

$$
P_{a,t}
=\left\{d\in D_t:
c_d=c_a,\ \operatorname{IoU}(B_a,B_d)>0\right\}.
$$

若 $P_{a,t}$ 非空，选与 anno **IoU 最大**的框 $d^*_{a,t}$。
若两个框的 IoU 完全相同，再选 conf 较高者；
仍相同则按预测框 ID 固定顺序。选框只依靠类别和几何重叠，
不让 conf 决定候选身份。

从**同一个** $d^*_{a,t}$ 读取两个数：

$$
S_{\mathrm{same,conf}}(a,t)=q_{d^*_{a,t}},
\qquad
S_{\mathrm{same,IoU}}(a,t)
=\operatorname{IoU}(B_a,B_{d^*_{a,t}}).
$$

若 $P_{a,t}$ 为空，则定义：

$$
S_{\mathrm{same,conf}}(a,t)=0,\qquad
S_{\mathrm{same,IoU}}(a,t)=0,\qquad
H(a,t)=0.
$$

若 $P_{a,t}$ 非空，令 $H(a,t)=1$。
$H$ 告诉我们这轮的两个数**是否来自真实保存的预测框**。
如果图像该轮根本没有完成推理，三项都应记为缺失，
不能记为 0。

### 一个数字例子

假设 anno 类别是“狗”，NMS 后有三条预测：

| 预测框 | 预测类别 | conf | 与 anno 的 IoU |
| --- | --- | ---: | ---: |
| A | 狗 | 0.80 | 0.60 |
| B | 猫 | 0.90 | 0.75 |
| C | 狗 | 0.45 | 0.70 |

框 B 类别不同，不参与选框。在两个“狗”框里，C 的 IoU 更高，
所以这一轮记录
$S_{\mathrm{same,conf}}=0.45$、
$S_{\mathrm{same,IoU}}=0.70$、$H=1$。
我们**不会**把 A 的 conf 0.80 和 C 的 IoU 0.70 拼成一对数字。
也不会因为 B 的 conf 最高就选 B。

如果删掉 A 和 C，这一轮没有同类重叠框，
记录两个支持度均为 0、$H=0$。
图中仍有“猫”框，但现有 JSON 无法告诉我们
这个“猫”框对“狗”类别打了多少分。

## 4. 两条 50 轮轨迹如何打分

对每个 anno 保存长度为 50 的两条序列：

$$
\boldsymbol{C}_a
=\bigl(S_{\mathrm{same,conf}}(a,0),\ldots,
S_{\mathrm{same,conf}}(a,49)\bigr),
$$

$$
\boldsymbol{I}_a
=\bigl(S_{\mathrm{same,IoU}}(a,0),\ldots,
S_{\mathrm{same,IoU}}(a,49)\bigr).
$$

另外保存 50 个 $H(a,t)$，方便把“有框但 conf / IoU 低”
与“根本没有同类重叠框”分开解释。
$H$ 是对两条轨迹的观测状态说明，不是第三种模型输出。
下面的特征以**该 anno 的 50 轮图像均完成推理**为前提；
若有未推理轮次，应先补齐对应 checkpoint 的推理结果，
不能把缺失轮次当作零检测后直接计算均值。

首版可以先提取四个简单过程特征，全部写成**越大越可疑**：

| 特征 | 计算方式 |
| --- | --- |
| 整体 conf 不足 | $1-\operatorname{mean}(\boldsymbol{C}_a)$ |
| 整体 IoU 不足 | $1-\operatorname{mean}(\boldsymbol{I}_a)$ |
| 后期 conf 不足 | $1-\operatorname{mean}_{t=40}^{49}S_{\mathrm{same,conf}}(a,t)$ |
| 后期 IoU 不足 | $1-\operatorname{mean}_{t=40}^{49}S_{\mathrm{same,IoU}}(a,t)$ |

前两项看完整训练过程，后两项看训练后期。
四项都来自同一套 conf / IoU 轨迹，对所有 anno 使用相同规则。
它们有相关性，因此等权 TOPSIS 只是首版基线；
应与“只用完整 50 轮均值”比较，检查后期特征是否真的带来收益。
后续还可在固定方案下消融首次出现相关框的 epoch、
后期连续无框轮数或早晚变化量。

先在不知道错误标签的情况下，按统一规则计算特征、
归一化并输出一个全体 anno 的可疑度排名。
**评价时**才把类别错误、位置错误、随机新增框统一记为 fault，
与 clean 做 AP、AUROC 和 Precision@K 比较。
不对不同 fault 类型设计不同公式或单独的排名。

### 为什么不把两个数直接相乘

乘积
$S_{\mathrm{same,conf}}(a,t)S_{\mathrm{same,IoU}}(a,t)$
会压缩不同的 conf / IoU 组合，
也会让论文难以分别讨论两种过程度量。
可以把乘积的 50 轮均值作为**对照实验**；
如果它更有效，应如实报告，但主方案仍保留原来的两条轨迹，
便于解释和复现。

## 5. 对全零轨迹要诚实

如果一个 anno 在 50 轮**都没有同类重叠框**，
则 $\boldsymbol{C}_a$ 和 $\boldsymbol{I}_a$ 都全为 0，
$H(a,t)$ 也都为 0。
两个这样的 anno 无论真实是 clean 还是 fault，
上述过程特征都相同，TOPSIS 必然给它们相同分数。
拆成 conf 与 IoU 两条轨迹也**不能解决这个信息缺失**。

因此在排序之前必须统计：

1. 50 轮都没有同类重叠框的 anno 有多少；
2. 50 轮都没有**任何类别**的 NMS 后框重叠的 anno 有多少。

完成排序后，才读取 clean/fault 真值，报告这两个集合各有多少
clean 和 fault。若全零组很大，论文需明确：
仅用当前阈值下的 NMS 后预测，无法区分这些 anno。
不应靠 anno ID、随机噪声，或远处无关预测框强行给它们不同分数。

### 当前 50 轮预测文件的只读覆盖统计

在 VOC / YOLOv7 / 注错率 0.1 / repeat 1、图像范围已对齐的
50 份 NMS 后预测 JSON 上，逐 anno 扫描得到：

| 规则 | 50 轮都没有关联框的 anno | 其中 clean | 其中 fault |
| --- | ---: | ---: | ---: |
| 原 <code>search_match_PG2</code>：同类、IoU $\geq0.5$、一对一 | 3,171 | 125 | 3,046 |
| 本方案：同类、IoU $>0$、逐 anno 独立选框 | 1,915 | 34 | 1,881 |
| 敏感性检查：同类、IoU $>0.1$ | 2,015 | 49 | 1,966 |
| 仅作上界参考：任意类别、IoU $>0$ | 244 | 9 | 235 |

因此本方案使原先从未正式匹配的 **1,256 个 anno**
至少有一轮出现同类重叠框，其中 clean 91 个、fault 1,165 个；
旧零匹配组缩小约 39.6%。这说明它确实缓解了“完全没有相关框”的问题，
但仍有 1,915 个 anno 的两条主轨迹全零。
其中 1,671 个至少与某个**异类**预测框重叠，244 个与任何类别的
NMS 后框都不重叠。最后一行不是本方案的同类选框规则，
只用于说明现有 NMS 后结果最多还包含多少额外的空间信息。
如果仍要求同类 IoU 大于 0.5，仅去掉一对一分配，
旧零匹配组只减少 22 个。因此这次覆盖改善主要来自
**允许 IoU 小于 0.5 的同类重叠框提供过程度量**。
而且**获得关联框不等于提高 clean/fault 排序效果**，
排序效果仍需按第 4 节的对照实验测量。

## 6. 什么时候需要重新推理

现有 [预测 JSON 收集脚本](../yolov7/collect_train_info.py)
保存了 NMS 后框的类别、conf 和坐标，已足够计算上面两条轨迹；
如果能确认全部图像在 50 轮都被处理，
**第一版无需重新运行 50 个 checkpoint**。

但脚本遇到一张图没有 NMS 后框时，会直接跳过它，
而不写空列表。因此要结合完整运行记录和图像清单确认：
JSON 里缺少某图，究竟是“已推理但零检测”，还是“没有处理该图”。
前者两条支持度记 0，后者记缺失。
若确有未处理图像，要补跑相应 checkpoint 的推理，
才能为其中的 anno 建立完整轨迹并参与全体排名。
以后重新收集时，建议把已推理但无检测的图显式写为
<code>predicted_bboxs: []</code>。

还要核对 50 份预测覆盖的图像范围与 anno 文件一致；
否则未被推理的图像会被错误解释为全零轨迹。
若 13,609 个 anno 的 50 轮都确实完成推理，
逐轮记录应有 $13{,}609\times 50=680{,}450$ 行。

如果未来想读取一个**预测成其他类别**的框对 anno 标注类别的分数，
现有 JSON 不够，需要重新运行 checkpoint，
并额外保存 NMS 后框的完整类别分数向量。
这是另一项扩展，不影响本文的两条主轨迹定义。

## 7. “冗余 fault”按你们代码的含义处理

根据 [<code>gen_redundancy_fault()</code>](../fault_inject.py)，
此处的冗余 fault 是在同一图像中**新增**一个 ID：
新框坐标在整张图范围内随机生成，类别随机抽取，
原有 anno 仍保留。它通常不是与原 anno 完全重合的复制框。

新增 anno 与其他 anno 一样，直接按第 3 节选框、
生成 conf / IoU 两条轨迹，并进入同一排名。
随机新增框可能碰巧覆盖真实物体，难检测的 clean anno
也可能长期没有相关框；方法的有效性取决于整体排序结果，
不能保证逐个样本都正确。

## 8. 实施与对照实验

1. 固定 50 份 NMS 后预测 JSON、anno 文件、图像列表、
   类别 ID 对应关系及 NMS 参数。
2. 从 anno 文件建立**全部** anno 的主表。
   不从旧 <code>match.json</code> 的键出发，
   否则从未匹配的 anno 会被遗漏。
3. 逐图逐轮按第 3 节选框，写出
   <code>anno_id</code>、<code>epoch</code>、
   <code>S_same_conf</code>、<code>S_same_iou</code>、
   <code>has_same_overlap</code> 和图像处理状态。
   同时保存旧规则的正式匹配结果供对照。
4. 统计全零轨迹和缺少推理的图像，完成数据覆盖检查。
5. 构建四项过程特征，输出一份 clean/fault 可疑度排名。
6. 读取评价标签，比较：现有八特征、只用 conf、
   只用 IoU、分开的 conf + IoU，以及 conf × IoU 对照方案。

只遍历已保存的 **NMS 后框**，无需枚举 NMS 前的大量候选。
本方案获得的是“与 anno 相关的 NMS 后框的 conf / IoU 支持轨迹”，
**不是 YOLOv7 原生逐 anno 训练 loss**。
